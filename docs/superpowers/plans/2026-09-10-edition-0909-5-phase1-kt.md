# Edition 0909_5 Phase 1 KT (BKT-first) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add flag-gated BKT knowledge tracing that fuses into five-dim `knowledge_mastery`, with no torch/pykt main dependency and no legacy behavior change when flags are off.

**Architecture:** Protocol + `BKTKnowledgeTracing` default via `create_kt_service()`; persist KT blob under `session.metadata["enhanced"]["kt"]`; `ProfileUpdaterAgent.update_session` uses BKT fusion when PROFILE+AGENTS+KT are on, else existing ±0.12. Fix `set_enhanced_profile` to merge `profile` without wiping sibling keys.

**Tech Stack:** Python 3.11+, Pydantic v2, existing `ilearn.core.enhanced_flags` (no PyYAML), pytest. Optional pyKT deferred (no adapter file required in this PR).

**Source of truth:** `docs/superpowers/specs/2026-09-10-edition-0909-5-phase1-kt-design.md`. Coding draft `doc/edition_0909_5_coding.txt` is a sketch only — **adapt** to real APIs below; do not paste it verbatim.

## Global Constraints

- Model name: `StudentFiveDimProfile` (never `EnhancedFiveDimProfile`)
- Flags module: `ilearn.core.enhanced_flags.is_enhanced_enabled` / `clear_enhanced_flag_cache` (never invent `feature_flags` or PyYAML loader)
- Profile API: sync `get_enhanced_profile(session)` / `set_enhanced_profile(session, profile) -> SessionState`
- Updater entry: sync `ProfileUpdaterAgent.update_session(session) -> SessionState` (orchestrator + background service); keep `_execute` delegating to it
- No `numpy`; use `max`/`min` for clamps
- No `torch` / `pykt-toolkit` in main deps; do **not** ship a full `pykt_adapter.py` in this PR
- Path rewrite: all under `ilearn/`
- Flags default off in `data/features.yaml`
- Fusion: `new = α * kt + (1-α) * old` with `α=0.4`; if `get_attempt_count(concept) < 3`, use `α_eff = 0.2` (coding-doc cold-start; still within design intent)
- KT on → do **not** also apply ±0.12 to the same `knowledge_updates`
- On KT exception → log + ±0.12 fallback; never raise out of `update_session`
- Commit only KT-related files; leave unrelated local junk (`doc/`, demo scripts, `relationships.json`) unstaged

- Add sync helper (method or small class) for KT fusion — **no async**, no `numpy`, no `profile_updater_old`

Logic inside `update_session` after signals extracted:

```text
if PROFILE and AGENTS:  # already gated at top
  if ENABLE_ENHANCED_KT:
    try:
      kt = create_kt_service_from_session(session, backend="bkt")
      for concept, correct in knowledge_updates.items():
          kt.add_interaction(str(concept), bool(correct))
      targets = set(knowledge_updates) | set(profile.cognitive.knowledge_mastery)
      preds = kt.predict_mastery(list(targets))
      for concept, kt_score in preds.items():
          if concept not in knowledge_updates and concept not in profile.cognitive.knowledge_mastery:
              continue  # defensive; targets already limited
          old = profile.cognitive.knowledge_mastery.get(concept, 0.5)
          alpha = 0.4 if kt.get_attempt_count(concept) >= 3 else 0.2
          profile.cognitive.knowledge_mastery[concept] = max(0.05, min(0.95, alpha * kt_score + (1 - alpha) * old))
      # rebuild weak/strong like CognitiveSubAgent
      set_kt_state(session, kt.get_state())
    except Exception:
      log; fall through to self._cognitive.update(profile, signals)
  else:
      profile = self._cognitive.update(profile, signals)
  # then emotional/behavioral/metacognitive unchanged
```

When KT succeeds, **skip** `self._cognitive.update` for that round.
